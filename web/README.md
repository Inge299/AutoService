# AutoService Web

Web-кабинет мастерской на Next.js: очередь визитов, карточка ремонта, клиенты, напоминания, аналитика и публичная страница согласования работ.

## Локальный запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

Для просмотра интерфейса без API установите в локальном `.env.local`:

```dotenv
AUTOSERVICE_DEMO_MODE=true
```

Demo mode работает только в development и никогда не обходит вход в production.

## Подключение к текущему серверу

Заполните `AUTOSERVICE_API_URL`, `AUTOSERVICE_WORKSHOP_ID` и `AUTOSERVICE_USER_ID`. Браузер обращается к серверной части Next.js, а она добавляет текущие development-заголовки `x-workshop-id` и `x-user-id` при вызове AutoService API. Эти заголовки не формируются клиентским JavaScript.

Уже поддержан существующий контракт сервера:

- readiness-проверка;
- upsert визита и находки;
- создание и завершение media upload session;
- получение статуса медиа.

Сейчас сервер не предоставляет list/read API для визитов, клиентов и напоминаний, а также endpoint для решения клиента. Поэтому эти разделы используют типизированный demo repository, а клиентское согласование помечено как предпросмотр. Подменять отсутствующий API фиктивным успешным запросом интерфейс не будет.

## Авторизация

Web использует зашифрованную и аутентифицированную `HttpOnly`, `SameSite=Lax` cookie на 12 часов. Проверки сессии выполняются и в layout, и рядом с доступом к данным. Пароль администратора хранится как scrypt-хеш. Сгенерировать его можно так:

```bash
npm run auth:hash -- "длинный-уникальный-пароль"
```

Результат сохраните только в `WEB_ADMIN_PASSWORD_HASH` локального окружения. `WEB_SESSION_SECRET` должен содержать не менее 32 случайных символов. `.env*` игнорируются Git, кроме безопасных `.env.example`.

Это переходная авторизация web/BFF, потому что текущий API использует доверенные development-заголовки и сам не выдаёт пользовательские токены. До production API должен получить полноценную проверку пользователя/роли; доступ к текущему серверу следует оставить только во внутренней сети или за reverse proxy. На публичном контуре также нужны rate limit для входа и HTTPS.

## Docker и VM

Production-образ использует минимальный standalone output Next.js и запускается от непривилегированного пользователя. Для VM создайте закрытый файл окружения на основе `deploy.env.example`, затем выполните:

```bash
docker compose --env-file deploy.env up -d --build
docker compose ps
```

По умолчанию web слушает только `127.0.0.1:3000`, чтобы его публиковал HTTPS reverse proxy. Для временного просмотра напрямую можно установить `WEB_BIND_ADDRESS=0.0.0.0`, ограничив порт firewall по нужным IP.
