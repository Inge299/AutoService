# Закрытие оставшихся ошибок QA

Основа — `d5b4431` (PR #57), с сохранением предыдущих исправлений.

- B11: помощь на публичном согласовании показывает только существующий телефон мастерской. Подсказка не предлагает исчезнувшую кнопку «Нужен звонок» ни после ответа, ни после перезагрузки. Без телефона лишний блок не выводится; доступные варианты решения остаются в форме до ответа.
- R01: новый пароль в API, Web и Android — от 5 до 256 символов. Правило применяется к выдаче временного пароля, административному сбросу, смене сотрудником и регистрации клиента. Проверка входа допускает короткий существующий пароль; действующие пароли не изменяются. Обязательная смена временного пароля, хеширование, ограничение попыток и отзыв сессий при административном сбросе сохранены.
- D01: serialization-core и serialization-json согласованы через BOM 1.8.1. Раньше приложение выбирало core 1.7.3, а Room testing — json 1.8.1, что приводило к AbstractMethodError до миграции. Тест 5→8 дополнен сохранением медиа и справочника, помимо визита и находки. Схема БД не меняется.

Ручные инструментальные проверки на TECNO:

1. `InstalledDataUpdateTest`: фаза capture на APK 102, обновление `adb install -r`, фаза verify на APK 103. Сравниваются хеши ID всех записей в установленных базах мастерских, без выгрузки персональных данных.
2. `NetworkRecoveryTest`: отдельные сессия и локальная база, фиксированная QA-мастерская. Подготовка кэша, отказ реального HTTP-транспорта на закрытом локальном TCP-порту, сохранение 242 визитов/незавершённого отчёта/медиа. Затем force-stop и новый процесс: сохранённые данные проверяются, сеть восстанавливается, одна синтетическая фотография загружается и повторяется с тем же ID.
3. `PasswordScreenTest`: кнопка сохранения недоступна на 4 символах и доступна на 5 совпадающих символах. Используется тестовый callback, действующий пароль пользователя не меняется.

Проверки обновления/сети запускаются по фазам через qaUpdatePhase/qaRecoveryPhase; для живого QA API нужны qaLogin/qaPassword в аргументах instrumentation. Без явных аргументов эти специальные сценарии пропускаются, чтобы обычный запуск тестов не обращался к Mia и не требовал определённой установленной версии APK. Тест сети использует видимую пустую Activity; настройки Wi-Fi, мобильной сети и VPN не меняет. Таймауты HTTP доступны для тестового экземпляра клиента, обычные значения приложения сохранены.

До отключения VPN пользователем запросы TECNO к Mia зависали на TLS; после отключения подготовка сетевого теста прошла за 5,6 с. Это ограничение проверенного сетевого маршрута, а не подтверждение работы со всеми VPN. Прерванные диагностические прогоны сохранены отдельно от успешных.

На TECNO все указанные явные фазы прошли: capture/verify обновления 102→103, расширенная миграция 5→8, подготовка кэша с отказом соединения, восстановление в новом процессе (12,2 с) с реальной загрузкой синтетического JPEG и идемпотентным повтором, экран пароля 4/5 символов. Это проверка повторной передачи файла целиком после отказа, не докачки по байтам из середины и не суточной автономной работы WorkManager. Подмена Wi-Fi/мобильной сети не выполнялась; отказ создавался отдельным тестовым HTTP-клиентом на закрытом TCP-порту.

Автоматические проверки: Server typecheck/build и 138 тестов с настоящей PostgreSQL без пропусков; Web lint/typecheck/build и 9 тестов; Android lint/build и 28 unit tests.

Визуальная проверка Web остаётся заблокированной: переключатель Browser в интерфейсе включён (скриншот пользователя), но инструмент после пересоздания сессии возвращает `Local browser use is disabled in Work settings`. Настройки пользователя не менялись и ограничение не обходилось. SSR, unit-тесты и сборка проверяются отдельно; они не заменяют проверку вёрстки.
