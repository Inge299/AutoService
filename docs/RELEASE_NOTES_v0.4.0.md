# AutoService v0.4.0

Дата выпуска: 19 сентября 2026.

## Что исправлено

- Android хранит очередь медиа, черновики согласований и отчётов отдельно для каждой мастерской. После перезапуска приложения незавершённые операции восстанавливаются с прежним ключом идемпотентности.
- Согласование создаётся только для сохранённого неизменяемого набора проверенных материалов. После готовности мастер сам выбирает канал через системное «Поделиться».
- Медиа нельзя изменить или удалить после включения в опубликованное согласование либо отчёт. Неисправимые ошибки показываются понятным текстом и могут быть повторены.
- Ремонт завершается версионированным отчётом: выполненные работы, рекомендации и дата следующего визита доступны клиенту в кабинете и по публичной ссылке. Согласованную работу можно отметить выполненной.
- Android, кабинет клиента, публичные страницы, страницы мастера и административные таблицы используют единые кнопки, ссылки и сообщения об ошибках.
- Сервер защищён serializable-транзакциями для согласований, решений клиента и отчётов; добавлены проверки гонок и повторных запросов.
- Production readiness проверяет PostgreSQL и MinIO. Логи не содержат токены, пароли, номера телефонов или OTP; каждое обращение имеет server-generated request ID.
- API и worker используют отдельный ключ MinIO с минимальными правами. Production presigned-ссылки требуют HTTPS; публичные API имеют ограничение частоты запросов.

## Проверки

- Server: 61 тест успешно, 1 интеграционный тест пропущен без отдельной PostgreSQL базы; typecheck и build успешны.
- Web: lint, typecheck и production build успешны.
- Android: lint, unit-тесты и компиляция инструментального теста миграции Room успешны.

## Известные условия выпуска

- Перед выдачей Android release APK в GitHub Actions должны быть заполнены четыре signing secret из [`android/README.md`](../android/README.md).
- На физическом Android-устройстве нужно пройти [`P0_ACCEPTANCE_CHECKLIST.md`](P0_ACCEPTANCE_CHECKLIST.md), включая запуск инструментального теста миграции.
- Off-host backup, регулярный restore drill, внешние алерты и политика хранения персональных данных остаются обязательной операционной работой до внешнего пилота.
