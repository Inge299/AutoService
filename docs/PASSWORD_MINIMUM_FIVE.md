# Минимальная длина пароля

По запросу владельца минимальная длина нового пароля составляет 5 символов,
максимальная остаётся 256. Более длинные пароли по-прежнему допустимы и рекомендуются,
особенно для администратора. Снижение минимума ослабляет устойчивость к подбору.

Единое ограничение применяется к созданию сотрудников, административному сбросу,
первой смене пароля сотрудника, а также регистрации и парольному входу клиента.
Веб-формы, Server Actions, API и Android-форма смены пароля согласованы.
Обычный staff-вход по-прежнему принимает старые короткие временные пароли:
новая политика проверяется при установке нового пароля, а не при аутентификации.

Хеширование scrypt, серверные ограничения числа попыток, проверка роли администратора,
отзыв сессий при административном сбросе и обязательная смена временного пароля
сохранены. Миграций схемы БД и массового сброса существующих паролей нет.

Тесты покрывают отклонение staff-паролей короче 5, принятие ровно 5 при создании,
смене и административном сбросе; клиентская регистрация тестируется с 5 символами.
Веб-тесты проверяют согласованность minLength и maxLength форм.

Операционный сброс конкретной учётной записи не включён в исходники: временные
пароли нельзя сохранять в репозитории или PR. До развёртывания этого изменения
на Mia и установки новой Android-сборки там остаются прежние ограничения длины.
