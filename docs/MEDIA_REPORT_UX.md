# Исправления поиска, медиа и итогового отчёта

- Поиск вынесен в общую форму `ListSearch`: поле и кнопка являются соседними
  элементами. При ширине до 460 px кнопка переносится под поле. Выбранный статус
  визита сохраняется при поиске.
- Карточка визита получает все подтверждённые материалы через staff API
  `/v1/visits/:id/media`. Вместо декоративных плиток отображаются фото, видео с
  управлением и аудиоплеер. Непроверенные файлы не получают download URL.
  Ссылки действуют 15 минут, их можно обновить без смены страницы. Все материалы
  остаются видны на телефоне, ограничение тремя плитками убрано.
- Напоминание использует отдельные области клиента, причины, состояния доставки
  и действия. На планшете/телефоне данные переносятся, кнопка отмены не обрезается.
- Android: отчёт открывается в прокручиваемом диалоге с отдельным нижним блоком
  кнопок. Публикация и отмена расположены вертикально с отступом. Выбор следующего
  визита — системный календарь либо неделя/месяц/3/6 месяцев, дату можно убрать.
- Выполненные находки подставляются в работы только по нажатию мастера. Готовые
  рекомендации добавляются как редактируемые строки без дублей. Пользовательский
  текст сохраняется, автоматических утверждений о выполнении ремонта нет.

Проверки: серверные тесты на выдачу трёх типов медиа и изоляцию мастерских;
Android unit-тесты локальной даты и добавления подсказок. UI-регрессия
`ReportComposerDialogTest` проверяет раздельные видимые кнопки и выбор срока на
разблокированном устройстве, публикуя только локальный синтетический ReportDraft.
Для web локальный стенд проверен на 1280 и 390 px с синтетическими файлами:
пересечений поиска нет, horizontal overflow нет, фото/видео/аудио загружаются.
Тестовый маршрут и фикстуры не входят в приложение.

## Повторный визит и отложенные работы

- Android-приёмка ищет в клиентской базе мастерской через `/v1/customers` по
  телефону или госномеру. После поиска показываются все автомобили найденного
  клиента, конкретная машина выбирается явно. Подставляются имя, телефон,
  автомобиль и госномер; текущий пробег и новые жалобы заполняются заново.
  Есть действие «Другой автомобиль этого клиента». Ошибка сети не выдаётся за
  отсутствие клиента. Результат ограничен 25 клиентами с просьбой уточнить поиск.
- Серверный поиск понимает форматированный телефон (включая начальную 8) и
  госномер с отделённым пробелом регионом. Область поиска ограничена мастерской.
- В рекомендации автоматически включаются находки DEFERRED независимо от
  приоритета и незавершённые PLANNED, кроме отклонённых. Формулировка явно говорит,
  что работа не выполнена сейчас и необходима в дальнейшем. COMPLETED не становится
  рекомендацией только из-за планового приоритета.
- В этой версии у таких работ общий срок — выбранная дата следующего визита.
  Без даты срок не выдумывается, мастер видит предупреждение об отсутствии
  автоматического напоминания. Индивидуальные сроки по каждой работе не добавлены.
- При публикации сервер сохраняет рекомендации в неизменяемую версию и в причину
  напоминания. Напоминание ставится за 7 дней до срока, но не раньше текущего
  момента. Повторная публикация с тем же operationId не создаёт дубль. Android
  также формирует текст, поэтому рекомендации сохраняются и до обновления API.
- Публичный отчёт показывает отдельно приоритет, статус исполнения и пояснение
  по будущим работам со сроком. Уже опубликованные версии не переписываются.
- Новый визит связывается с напоминанием только по тому же автомобилю, а не просто
  по телефону владельца: приём второй машины не отменяет напоминание по первой.

Проверки этой части: серверные тесты поиска/публикации/причины напоминания и
выбора автомобиля, Android unit-тесты формирования рекомендаций. Новые экранные
тесты `RepeatVisitIntakeTest` и обновлённый `ReportComposerDialogTest` используют
синтетические данные и не обращаются к серверу. После подключения TECNO все три
экранных теста пройдены: обработка ошибки поиска, выбор второго автомобиля клиента
с передачей данных в новый визит и добавление отложенной работы со сроком в отчёт.

При проверке на TECNO после подключения обнаружено перекрытие нижних действий
приёмки экранной клавиатурой. В версии 88 форма учитывает IME-insets через
`imePadding`; тест прокручивает LazyColumn до ещё не скомпонованных полей, а не
полагается на наличие внеэкранных элементов в дереве. Обновление устанавливается
через `adb install -r`, без удаления приложения и его данных.
Версия 88 установлена на TECNO; после тестов открыто основное приложение.
