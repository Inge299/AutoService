# Серверный контракт первого пилота

## Граница этапа

Android остаётся источником локальных черновиков и медиа-очереди. Сервер становится источником правды после успешной синхронизации и создаёт публичные клиентские ссылки. До развёртывания в приложении работает только локальный предпросмотр.

## Минимальные сущности

- `workshops`, `users`, `devices` — изоляция данных мастерской и авторизация сотрудника;
- `visits`, `findings`, `media_assets` — серверные версии объектов Android;
- `approval_links` — случайный одноразовый токен, срок жизни, статус открытия и решения;
- `approval_decisions` — неизменяемая запись решения, времени, версии находки и источника;
- `sms_messages` — постановка в очередь, результат доставки, провайдерский идентификатор.

## API v1

| Операция | Метод и путь | Назначение |
|---|---|---|
| Синхронизация визита | `PUT /v1/visits/{id}` | идемпотентная передача Android-черновика |
| Синхронизация находки | `PUT /v1/findings/{id}` | передача цены, текста, приоритета и статуса |
| Начало загрузки | `POST /v1/media/{id}/upload-session` | выдача resumable upload URL; ключ — `operationId` |
| Подтверждение файла | `POST /v1/media/{id}/complete` | размер и SHA-256 должны совпасть с Android |
| Создать согласование | `POST /v1/findings/{id}/approval-link` | фиксирует версию находки и возвращает публичный URL |
| Открыть клиентскую страницу | `GET /a/{token}` | без регистрации; только данные конкретного согласования |
| Решение клиента | `POST /a/{token}/decision` | `approved`, `declined`, `deferred`, `call_requested`; одно итоговое решение |
| Отправить SMS | `POST /v1/approval-links/{id}/send-sms` | серверная очередь, журнал доставки |

## Обязательные правила безопасности

1. Публичный токен — не ID находки, а случайное криптографическое значение не менее 128 бит; хранится только его хеш.
2. Решение возможно один раз; повторный запрос возвращает уже зафиксированный результат.
3. В ссылке фиксируются версия текста, цена и список материалов, показанные клиенту.
4. Медиа доступны клиенту только через короткоживущие подписанные URL и только из конкретного согласования.
5. Android использует авторизацию сотрудника, `operationId` и SHA-256 для идемпотентной синхронизации.

## Что потребуется от владельца перед боевым запуском

- домен для клиентских ссылок;
- выбранный хостинг и доступ к нему;
- договор и реквизиты SMS-провайдера;
- согласованный текст сервисного SMS и политика обработки персональных данных.
