# Контракт серверного пилота

## Реализовано

Сервер — источник истины для визитов, находок и медиа. Android создаёт и меняет визит
только через API, а Room использует как кэш отображения и устойчивую очередь медиа до
серверного подтверждения SHA-256.

| Операция | Метод и path | Статус |
|---|---|---|
| Liveness | `GET /health/live` | Реализовано |
| Readiness и PostgreSQL | `GET /health/ready` | Реализовано |
| Синхронизация визита | `PUT /v1/visits/{id}` | Реализовано |
| Синхронизация находки | `PUT /v1/findings/{id}` | Реализовано |
| Начало загрузки | `POST /v1/media/{id}/upload-session` | Реализовано |
| Подтверждение файла | `POST /v1/media/{id}/complete` | Реализовано |
| Статус файла | `GET /v1/media/{id}` | Реализовано |
| Вход Android | `POST /v1/auth/login` | Реализовано |

Детали запросов, ответов и ошибок описаны в [серверной архитектуре](SERVER_ARCHITECTURE.md).

## Следующий этап

| Операция | Планируемый path | Статус |
|---|---|---|
| Создать согласование | `POST /v1/findings/{id}/approval-link` | Не реализовано |
| Открыть клиентскую страницу | `GET /a/{token}` | Не реализовано |
| Решение клиента | `POST /a/{token}/decision` | Не реализовано |
| Отправить SMS/сообщение | `POST /v1/approval-links/{id}/send-message` | Не реализовано |

Для согласований уже заложены таблицы `approval_versions`, `approval_links` и `approval_decisions`. Таблицы доставки сообщений пока нет: её нужно проектировать после выбора провайдера.

## Правила будущего публичного согласования

1. Публичный токен — случайное криптографическое значение не менее 128 бит; в БД хранится только хеш.
2. Решение фиксируется один раз; повтор возвращает уже записанный результат.
3. Фиксируются текст, цена и список медиа, которые видел клиент.
4. Медиа выдаются по короткоживущим presigned URL только из конкретного согласования.
5. Отправка сообщений идёт через очередь с журналом доставки и provider message ID.

## До боевого запуска нужны

- домен и TLS;
- production-авторизация;
- выбранный канал доставки и реквизиты провайдера;
- текст сервисного сообщения и политика обработки персональных данных.
