# AutoService

Нативный Android-клиент мастера для работы с серверной системой AutoService.

Основные требования находятся в [проектном документе](docs/PROJECT_BRIEF.md). В текущей
версии визиты и находки создаются на сервере через HTTPS API. Room не является источником
истины: он хранит только локальный кэш интерфейса и очередь медиа до подтверждения сервером.

Локальная проверка:

```bash
./gradlew lintDebug testDebugUnitTest assembleDebug --no-configuration-cache
./gradlew :android:app:connectedDebugAndroidTest
```

Ручной сценарий проверки описан в [ADR-0001](docs/adr/0001-offline-media-sync.md).

## Серверная работа Android

- пользователь входит по SMS на рабочий номер или под учётной записью, созданной администратором веб-кабинета;
- Android получает короткоживущий access-токен и одноразово ротируемый refresh-токен, без встроенных серверных ключей;
- сессия зашифрована AES-GCM ключом из Android Keystore; открытые токены старых версий удаляются;
- access-токен обновляется до истечения, конкурентные запросы используют одну ротацию, а выход отзывает серверную сессию;
- визит, начало ремонта и находка сначала подтверждаются API и затем обновляют локальный кэш;
- фото, видео до 30 секунд и голос сначала фиксируются в закрытом хранилище телефона;
- Room хранит постоянную очередь и состояния каждого материала только до серверной проверки;
- WorkManager ждёт сеть, переживает закрытие приложения и перепланирует работу после перезапуска устройства;
- повторная отправка идемпотентна по `operationId`, размер и SHA-256 проверяются с обеих сторон транспорта;
- для согласования Android создаёт одноразовую публичную ссылку для подтверждённого набора материалов и передаёт её через системное меню; решение принимает только клиент на публичной странице; серверная отложенная доставка после загрузки материалов запланирована следующим этапом;
- при запуске восстанавливаются завершённые файлы, если процесс остановился между фиксацией файла и записью Room.

Медиа загружаются напрямую в серверное S3-совместимое хранилище по короткоживущему presigned URL,
а сервер подтверждает контрольную сумму в фоновой очереди.
